① 什么是前端路由？

页面切换的发展历程

时代方式谁控制跳转体验
2000年后端渲染（PHP/JSP）后端整页刷新，慢
2005年Ajax 局部刷新后端为主局部刷新，好一点
2010年SPA 前端路由前端无刷新，极快
现在SSR 混合（Next.js）前后端配合首屏快 + 切换快

前端路由的核心原理

切换路由时不会向服务器发请求，只是 JS 在浏览器中切换不同的组件。
打开 F12 → Network 面板，在页面间切换，你会发现没有新的页面请求。

传统跳转 = 换台时重新开机。前端路由 = 换台只是切信号，电视不关机。

第1步：创建页面组件

// src/page/Login/index.js
const Login = () => {
  return <div>我是登录页</div>
}
export default Login

第2步：创建路由表

import { createBrowserRouter } from 'react-router-dom'
import Login from './page/Login'
import Article from './page/Article'

const router = createBrowserRouter([
  { path: '/', element: <Login /> },
  { path: '/login', element: <Login /> },
  { path: '/article', element: <Article /> },
])

第3步：注入应用入口

import { RouterProvider } from 'react-router-dom'

ReactDOM.createRoot(document.getElementById('root')).render(
  <React.StrictMode>
    <RouterProvider router={router} />
  </React.StrictMode>
)
RouterProvider 的作用类似 Redux 的 Provider：把路由能力注入整个应用。
③ 两种跳转方式：声明式 vs 命令式

声明式 Link 组件

import { Link } from 'react-router-dom'

// 写在 JSX 里，用户点击触发跳转
<Link to="/article">跳转到文章页</Link>

适合：导航菜单、页面中的链接

命令式 useNavigate 钩子

import { useNavigate } from 'react-router-dom'

const navigate = useNavigate()

// 在 JS 逻辑中触发跳转
<button onClick={() => navigate('/article')}>跳转</button>

适合：登录成功后自动跳转、代码逻辑中的跳转

对比Link（声明式）useNavigate（命令式）
写在哪JSX 模板中JS 逻辑中
触发方式用户主动点击代码自动触发
典型场景导航菜单、链接登录成功后跳首页
// 典型场景：登录成功后自动跳转
const onLogin = async () => {
  await axios.post('/api/login', { username, password })
  navigate('/home') // 登录成功 → 自动跳到首页
}
Link = 电梯按钮（按了就去对应楼层）。useNavigate = 你在代码里写"请去3楼"（程序自动执行）。
④ 嵌套路由 + Outlet（布局路由）

场景：固定导航 + 变化内容

┌─────────────────────────────┐
│  顶部导航栏（固定不变）         │
├──────┬──────────────────────┤
│  侧边 │  <Outlet />              │
│  目录 │  这里的内容随路径变化   │
│（不变）│  /board → 面板         │
│      │  /about → 关于         │
└──────┴──────────────────────┘

路由配置：用 children 嵌套

const router = createBrowserRouter([
  {
    path: '/',
    element: <Layout />, // 父路由（外壳，不变的部分）
    children: [ // 子路由（变化的部分）
      { path: 'board', element: <Board /> },
      { path: 'about', element: <About /> },
    ]
  }
])

Layout 组件：用 Outlet 占位

import { Outlet, Link } from 'react-router-dom'

const Layout = () => {
  return (
    <div>
      <div>我是Layout</div>
      <Link to="/board">面板</Link>
      <Link to="/about">关于</Link>
      {/* 二级路由出口 */}
      <Outlet /> ← 子路由的组件渲染在这里
    </div>
  )
}

Outlet 是什么？

<Outlet /> = 子路由的占位符。
告诉 React："子页面渲染在这个位置"。
就像一个相框：框不动，里面的照片随路径切换。

⑤ 默认二级路由（index 路由）

问题：访问 / 时 Outlet 是空的

// 之前：访问 / 时 Outlet 里没有内容
children: [
  { path: 'board', element: <Board /> },
  { path: 'about', element: <About /> },
]

解决：设置默认子路由

// 去掉 path，加 index: true
children: [
  { index: true, element: <Board /> }, // ← 默认显示！
  { path: 'about', element: <About /> },
]
访问路径之前（无 index）之后（有 index）
/Layout + Outlet 空白 ❌Layout + Board ✅
/aboutLayout + AboutLayout + About
index: true = 电视开机默认频道。打开电视（访问 /）→ 自动播 CCTV1（默认显示 Board）。
⑥ 路由导航传参

方式1 searchParams 传参（查询字符串）

// 跳转时：参数放在 ? 后面
navigate('/article?id=1001&name=jack')

// 接收时：
const [params] = useSearchParams()
let id = params.get('id') // '1001'
let name = params.get('name') // 'jack'

URL 样子：/article?id=1001&name=jack

方式2 params 传参（路径参数）

// 路由表要配占位符：
{ path: '/article/:id', element: <Article /> }

// 跳转时：参数直接在路径里
navigate('/article/1001')

// 接收时：
const params = useParams()
let id = params.id // '1001'

URL 样子：/article/1001

对比searchParamsparams
URL/article?id=1001/article/1001
传多个参数方便，用 & 连接不太方便
路由表不需要改需要加 :id 占位符
取值方式params.get('id')params.id
常见场景搜索、筛选、分页文章详情、用户主页
searchParams = 快递单写备注（地址：/article，备注：id=1001）。params = 直接写在地址里（/article/1001）。
⑦ 404 路由（兜底路由）

场景：用户访问不存在的路径

第1步：写 NotFound 组件

const NotFound = () => {
  // 自定义 404 页面
  return <div>404 - 页面不存在</div>
}

第2步：路由表末尾加 path: '*'

const router = createBrowserRouter([
  { path: '/', element: <Layout /> },
  { path: '/login', element: <Login /> },
  { path: '*', element: <NotFound /> }, // ← 放最后！兜底
])

* 通配符的含义

* = 匹配所有路径。路由从上往下匹配，前面都没命中时，最后被 * 兜住。
就像前台名单：张三→A室，李四→B室，其他人→请去404休息室。

⑧ 两种路由模式：History vs Hash

History 模式 主流

// URL: http://localhost:3000/login （干净，没有 #）
const router = createBrowserRouter([...])

Hash 模式

// URL: http://localhost:3000/#/login （有 # 号）
const router = createHashRouter([...])
对比History 模式Hash 模式
URL 样子/login/#/login
美观✅ 好看❌ 有 # 号
底层原理history.pushState监听 hashChange 事件
需要后端支持需要不需要
部署难度需要后端配置随便放就能用
创建函数createBrowserRoutercreateHashRouter

为什么 History 模式需要后端支持？

React 打包后只有一个 index.html，没有 login.html。

History 模式：用户直接访问 /login → 浏览器向服务器请求 /login → 服务器没有这个文件 → 404 ❌
解决：后端配置"所有路径都返回 index.html"，然后 React Router 接管。

Hash 模式：访问 /#/login → 浏览器只请求 /（# 后面的不会发给服务器，这是 HTTP 协议规定）→ 服务器返回 index.html → 永远不会 404 ✅

怎么选？
公司项目 → History 模式（主流，URL 好看，后端配合一下就行）
个人项目懒得配服务器 → Hash 模式（省事）

⑩ 补充：GET vs POST vs PUT vs DELETE

前端能发 HTTP 请求吗？当然能！

// axios（最常用）
const res = await axios.get('/api/articles')

// fetch（浏览器原生）
const res = await fetch('/api/articles')

四种请求方法（RESTful 规范）

方法用途参数位置示例
GET查数据URL 里（可见） GET /api/articles?page=1
POST增数据请求体（隐藏） POST /api/login {user, pwd}
PUT改数据请求体（隐藏） PUT /api/articles/1 {title}
DELETE删数据URL 里 DELETE /api/articles/1
注意：PUT 和 DELETE 不是必须的，POST 也能完成同样的事。分开用是为了接口更清晰（RESTful 规范）。小团队全用 GET + POST 也完全没问题。
GET = 看菜单（只读）。POST = 下单（创建）。PUT = 换菜（修改）。DELETE = 退菜（删除）。
